Proposed release plan · after v0

From boot demo to interactive system

v0 proves the vertical slice. v1 makes that slice useful repeatedly: type at a serial terminal, launch isolated Zig programs by path, wait for them, inspect files, recover their resources, and do it again without rebooting.

01

Make the existing mechanisms composable

The next release should turn the v0 demonstrations into services that programs can use over time. It should not restart the project around a larger list of hardware features.

v1 must

Complete the control loop

  • Receive serial input without polling or losing bytes.
  • Block tasks on input, timers, and child completion.
  • Load, run, exit, wait, and reclaim processes repeatedly.
  • Expose read-only files through descriptors rather than loader-only APIs.
  • Run the shell and commands as ordinary EL0 programs.
Not in v1

Do not multiply state spaces yet

  • No SMP, kernel preemption, or general spinlock layer.
  • No writable filesystem, page cache, or crash recovery.
  • No fork, copy-on-write, general signals, pipes, or background jobs.
  • No networking, USB, graphics, dynamic linking, or Linux ABI.
  • No FP/SIMD context switching; keep the v0 trap policy.

Why SMP waits: blocking, process teardown, descriptors, and the VFS establish the ownership and synchronization boundaries that SMP would need. Adding cores first would force locking decisions into demo-shaped structures and make lifecycle bugs much harder to isolate.

02

Close v0 before widening the contract

v1 begins from a released, reproducible baseline—not from the current QEMU-only midpoint. Preserve v0 as a regression profile while the normal boot path becomes interactive.

v0 exit

Deterministic vertical slice

Two isolated static Zig programs load from read-only FAT, run under timer preemption, and pass the same automated demo on QEMU and a physical Pi 4.

→
v1 entry

Frozen regression baseline

Tag the v0 release, retain its serial transcript as smoke-v0, document frame counts and fixed limits, then add a separate interactive boot profile.

Measure first

Record free frames, page-table use, boot time, and task slots before and after the v0 demo. These become leak and regression oracles.

Separate tests from policy

Keep deliberate faults and progress counters in the v0 smoke profile. The production profile should boot init, not run kernel self-tests forever.

Keep hardware honest

Do not start v1 board features until the complete v0 storage and two-process gates pass on the physical Pi.

Planning assumption: v0 Phase 9 storage passes on QEMU, but its polling virtio path and load-by-slice interfaces remain demo contracts. Phase 10 implements Pi SD parity, GIC/timer preemption, and the same isolated-process path; their physical timing and hardware behavior remain unverified. Revisit V1.0, V1.3, and V1.4 estimates after the v0 hardware gate rather than treating the QEMU interfaces as final.

03

Put policy in userspace and waiting in the kernel

The shell parses commands; the kernel owns resources and blocks work. A tiny PID 1 is the recovery anchor. Static mounts and bounded tables keep the first interactive release auditable.

PID 1 · initStarts the shell, adopts orphans, reaps any child, and starts a new shell after a fault.
Serial shellLine editing, path resolution, built-ins, foreground spawn, Ctrl-C break, and wait.
Zig commandsStatic EL0 executables with argc/argv and inherited descriptors 0, 1, and 2.
Versioned userspace ABIChecked pointers · file descriptors · process handles · stable errors · no Linux compatibility claim
Process + schedulerReusable slots, parent/child state, cancellation-safe waits, deadlines, idle task, frame ownership.
Read-only VFS/rom initramfs · /disk FAT · open/read/close/stat/readdir · internal read-at.
TerminalPL011 RX interrupt, bounded ring, blocking reads, foreground break, polled panic output.

The mount table is fixed at boot. There is no mount syscall, global current directory, terminal escape parser, or kernel command interpreter in v1.

Bounded by design

Start with explicit compile-time capacities: 16 process slots, 16 descriptors per process, 16 arguments, 256-byte paths and shell lines, and a 512-byte UART RX ring. Exhaustion returns a stable error; it never silently corrupts state.

No general kernel heap yet

Allocate user pages and translation tables from the frame allocator, but use reusable fixed pools for tasks, process records, file descriptions, and waiters. Add a kernel heap only when measured fragmentation or object diversity justifies it.

04

Define one coherent feature set

Everything marked “must” contributes directly to the release promise. “Should” work may enter only after all must-have gates are green on both targets.

Must

Blocking scheduler

Runnable, blocked, sleeping, zombie, and free states; cancellation-safe wait queues for RX, timers, and child exits; an idle task using wfi.

Must

Process lifecycle

Monotonic PIDs, parentage, spawn, exit, wait for one or any child, orphan adoption, fault termination, and complete frame, mapping, stack, slot, and descriptor reclamation.

Must

Interactive terminal

Interrupt-driven PL011 receive, overflow accounting, CR/LF normalization, blocking byte reads, shell-owned editing, and Ctrl-C termination of only the foreground child.

Must

Files and descriptors

A read-only VFS over initramfs and FAT, per-process descriptor tables, reference-counted inherited file descriptions, directories, and checked user buffers.

Must

PID 1 and shell

A rescue-capable initramfs shell with help, echo, pwd, cd, ls, cat, run, uptime, and reboot.

Must

Program contract

Initial user stack with argc/argv, inherited stdin/stdout/stderr, documented limits, stable errors, and an ABI epoch frozen for the v1 release.

Should

Small diagnostics

ps and mem backed by one versioned, read-only system snapshot API; include only if it does not expose internal pointers or unstable layouts.

Should

Usability polish

Command history, tab completion from one directory, and ANSI color detection are optional and may not complicate the terminal or VFS contracts.

Deferred

Persistence and parallelism

Filesystem writes, pipes, jobs, SMP, FP/SIMD, sockets, and dynamic executables each require a separate design and release gate.

05

Build from ownership to interaction

Each phase has an observable gate and leaves the kernel in a valid state. The order prevents UART, filesystem, and process-lifecycle bugs from arriving together.

V1.0
Baseline

Freeze v0 and split boot profiles

Complete every v0 exit criterion, capture QEMU and Pi transcripts, and preserve the exact self-test sequence behind a build option. Make the normal boot path enter a placeholder init task.

v0 tagsmoke-v0boot profilemetrics
Exit: the QEMU v0 transcript is byte-for-byte stable, the Pi transcript preserves the required marker sequence, and the normal profile reaches V1:INIT on both.
V1.1
Foundation

Task states, wait queues, and monotonic deadlines

Replace the runnable bitmap with explicit states. Add IRQ-safe wait, wake, and cancellation operations for a single core, timer deadlines, and a permanent idle task. A blocked task must be removable during fault or process teardown. Keep scheduler policy round-robin.

blockedsleepingwait queuecancelwfi
Exit: host tests cover lost-wakeup and blocked-task cancellation boundaries; QEMU proves sleepers wake in order and an all-blocked system idles without a busy loop.
V1.2
Ownership

Reusable processes and frame-backed address spaces

Separate PID from table slot. Replace embedded process memory and inline translation-table pools with allocator-owned frames, add table teardown, and implement spawn-from-bytes, exit, wait-one, wait-any, reap, and orphan adoption. Keep fixed object pools and make every partial-load error unwind.

pidspawnwaitreapunmap
Exit: one kernel harness performs 128 spawn/fault/exit/wait cycles and ends with exactly the initial free-frame, task-slot, and process-slot counts.
V1.3
Input

Interrupt-driven serial receive

Add PL011 RX interrupt support to both BSPs, a 512-byte single-producer/single-consumer ring, overflow counters, blocking terminal reads, and a single foreground PID. Ctrl-C terminates that child with an interrupted status; it does not introduce user signal handlers. Preserve the allocation-free polled path for panic output.

pl011 rxgicring bufferblocking readbreak
Exit: a scripted 4 KiB burst has no reordering or silent loss; blocked readers wake once; QEMU reports the exact injected overflow count, while Pi detects, counts, and exposes overflow without requiring timing-dependent equality.
V1.4
Files

Read-only VFS and descriptor tables

Adapt the v0 initramfs and FAT readers behind a path-based VFS with fixed mounts at /rom and /disk. Add reference-counted open file descriptions, per-process descriptors, internal positional reads, stat and directory iteration, and cleanup on close or exit. The ELF loader reads fixed-size headers, then streams segments directly into allocated frames; it never needs a whole-file kernel buffer.

vfsfdread atinitramfsfatreaddir
Exit: host tests reject malformed and escaping paths; two processes read the same file independently; inherited descriptors remain valid after parent close; descriptor and block-read failures leak no slots or frames.
V1.5
Userspace

Define provisional ABI epoch 2, then boot init and the shell

Move from the v0 console-shaped ABI to descriptor I/O, child lifecycle, time, and path operations. Build the initial argc/argv stack, launch PID 1 and the shell from initramfs, and run external commands from /disk/bin. Foreground spawn registers one terminal-owned child so Ctrl-C can end a runaway command without a general signal system.

abi 2argc/argvpid 1shellcommands
Exit: an automated serial session lists FAT files, cats a multi-block file, runs a command with arguments, observes its exit status, interrupts a runaway command, and returns to the prompt.
V1.6
Hardening

Fault containment and resource pressure

Make bad pointers, unknown syscalls, malformed ELF files, descriptor exhaustion, out-of-frame conditions, and user faults terminate or fail only the responsible operation. Add task/PID/ESR context to unexpected kernel exceptions.

fault isolationoombad elfleak checks
Exit: the shell survives every negative fixture and completes 128 mixed command launches with unchanged resource counters and no stale TLB access.
V1.7
Release

Freeze ABI epoch 2, prove Raspberry Pi parity, and cut v1

After the shell and hardening fixtures settle status records and errors, freeze epoch 2. Run the identical filesystem image, userspace binaries, ABI tests, shell transcript, and lifecycle stress on QEMU virt and physical Pi 4. Document serial setup, limits, recovery, and known omissions.

Exit: both targets emit V1:INTERACTIVE_OK after the scripted session; a human can then continue using the prompt without rebooting.
06

Freeze a small ABI around resources

The current ABI is explicitly experimental and console-shaped. Define epoch 2 provisionally for the first shell, freeze it only at the v1 release candidate after hardening, retain epoch 1 only in the v0 smoke profile, and avoid promising POSIX behavior.

read / write

Operate on descriptors with checked user slices. Descriptors 0, 1, and 2 are inherited terminal streams. Short reads and writes are valid.

open / close

Read-only open flags in v1. Paths are copied, length-bounded, normalized in the VFS, and never retained as user pointers.

stat / readdir

Use fixed-width, versioned records. Directory iteration has an explicit cursor; it does not expose FAT offsets or kernel object layouts.

spawn / wait / exit

Spawn a static AArch64 ELF by path with bounded arguments and inherited standard descriptors. A foreground flag binds one child to terminal Ctrl-C. Wait accepts a specific child PID or “any child,” returns the reaped PID, and copies a fixed-width exited, faulted, or interrupted status to a checked user pointer.

clock / sleep

Expose monotonic time in nanoseconds and sleep to an absolute deadline so user code never depends on the hardware timer frequency.

grow / yield

Keep bounded heap growth with documented page alignment. Retain yield for tests and cooperative programs, but normal waiting uses blocking calls.

reboot

Permit PID 1 or the foreground shell to request a documented platform reset. If a target cannot reset reliably, halt with a machine-readable marker.

Error model

Keep negative integer errors, add explicit values for bad descriptor, not found, not a directory, table full, not a child, interrupted/faulted child, and read-only operation. Unknown epochs remain rejected.

Initial stack contract

Enter at the ELF entry with a 16-byte-aligned stack containing copied UTF-8 argument strings and an argc/argv vector. No environment, auxiliary vector, dynamic loader, or libc contract in v1.

07

Test long-lived behavior, not only boot

The important v1 failures happen on the second or hundredth operation: a stale mapping, lost wakeup, child that was not reaped, leaked descriptor, or full ring. Resource counters become part of the test contract.

08

Protect ownership and wakeup invariants

v1 adds fewer hardware mechanisms than v0, but it introduces long-lived mutable state. Make invariants explicit before optimizing.

RiskSeverityRequired mitigation
Lost wakeupHighCheck condition and enqueue with local IRQs masked; wake after publishing data/state; test both sides of the interrupt-versus-block boundary.
Use-after-reapHighSeparate monotonic PID from reusable slot, define zombie ownership, and invalidate task/process links before frames return to the allocator.
Stale translationHighUnmap before freeing frames, perform the architecturally required TLB invalidation and barriers, and stress immediate slot/address reuse.
Partial spawn leakHighGive creation one unwind path with an ownership ledger for ELF pages, tables, stack, arguments, descriptors, process slot, and task slot.
UART overrunMediumDrain hardware FIFO in the IRQ, use a bounded ring, count drops, wake readers after publishing, and make overflow visible.
Filesystem policy leakMediumKeep FAT details behind a read-only backend; normalize paths once; do not expose sectors, clusters, or host structure packing in the ABI.
Shell in kernelMediumOnly the early rescue marker and panic path stay privileged. Parsing, editing, built-ins, and command dispatch all run at EL0.
Scope creepMediumForeground jobs, fixed mounts, static ELF, read-only storage, one core, integer state, and explicit limits are release constraints.
09

v1 is done when the prompt remains trustworthy

A prompt appearing once is not the gate. The system must survive useful work, failures, and resource reuse on both supported machines.

  • Every v0 definition-of-done item still passes.
  • Normal boot starts PID 1 and an EL0 serial shell.
  • QEMU and Pi use the same ABI and user ELF files.
  • Terminal input blocks and wakes without busy polling.
  • Shell can navigate and read initramfs and FAT files.
  • External commands receive bounded argc/argv.
  • stdin, stdout, and stderr are inherited descriptors.
  • Spawn, exit, wait, fault, and reap are observable.
  • PID 1 adopts orphans and recovers a failed shell.
  • Ctrl-C ends a runaway foreground child and restores the prompt.
  • 128 mixed launches leave all resource counts unchanged.
  • Bad pointers and malformed ELF never panic the kernel.
  • Full tables and out-of-memory return stable errors.
  • Unexpected kernel faults report task, PID, ESR, ELR, and FAR.
  • The v1 scripted serial transcript passes on physical Pi 4.
  • README documents commands, limits, ABI, and recovery.
  • No writable storage or secondary core is enabled.
10

Use v1 as the dependency base for later releases

These are next candidates, not hidden v1 stretch goals. Choose one release theme after usage shows where the system is most constrained.

Concurrency track

SMP and synchronization

Start secondary cores, add per-CPU state, replace local IRQ critical sections with explicit locks where ownership crosses cores, use targeted TLB shootdowns, and test scheduler fairness. v1’s wait and ownership boundaries are the prerequisite.

Persistence track

Writable data filesystem

Add a cache and ordered write contract on a dedicated data partition—not the firmware boot FAT by default. Define power-loss expectations before exposing create, truncate, or rename.

Compute track

FP/SIMD userspace

Save and restore architectural vector state, define lazy or eager ownership, update exception handling, and enable Zig code generation only after cross-task leakage tests pass.

Connectivity track

Networking and pipes

Build stream and readiness semantics on v1 descriptors, blocking, timers, and bounded buffers. Start with virtio-net in QEMU before selecting a Pi Ethernet/USB path.

Recommended next release after v1: choose SMP if the goal remains kernel-mechanism learning; choose writable data storage if the goal shifts toward practical standalone use. Do not combine both in one milestone.
